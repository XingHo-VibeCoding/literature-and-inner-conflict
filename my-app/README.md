# 文学与内心冲突｜本地运行说明

这是 Day 7 的本地 MVP。页面包含日精进记录与回看、人工书库、两类阅读推荐、收藏和备注。分析与阅读讲解目前只提供明确标注的固定虚构演示，尚未接入真实 AI 服务。

## 启动页面

需要 Node.js `^20.19.0` 或 `>=22.12.0` 和 npm。在 Windows PowerShell 中运行：

```powershell
cd "E:\vibe coding\my-app"
npm ci
npm run dev
```

首次或依赖尚未安装时运行 `npm ci`；若已安装依赖，之后只需 `npm run dev`。终端显示本地地址后，在浏览器打开 **http://localhost:5173/#/**。开发服务器需要保持运行；要停止时，在运行它的终端按 `Ctrl+C`。端口 5173 已被占用时，先停止占用该端口的服务，再启动本项目。

## 核对页面

1. 首页应显示“文学与内心冲突”，并能进入“自总结投放分析”和“书单推荐讲解”。
2. 日精进页可以用**虚构**文字和日期保存记录；刷新后，原文与日期仍应可回看。固定分析演示只适用于页面提供的指定虚构示例，不会把同一段分析套到其他记录。
3. 书单页应显示 6 本作品。选择“正在重新思考怎样生活”和“尝试更简朴的生活”，点击“查看两类推荐”；从“映照当下”打开《瓦尔登湖》，点击“查看固定演示讲解”，应看到演示标记、阅读问题和资料来源。切换到“探索改变”打开同书时，推荐理由和讲解应对应另一组。
4. 收藏与备注保存在当前浏览器；刷新后可核对已保存内容。推荐条件和固定阅读讲解只留在当前页面会话，刷新后需要重新选择。

本地数据按浏览器及网站地址隔离；换浏览器、换设备或清理浏览器数据后，不能依靠此版本找回原记录。真实 AI 生成、模型超时及联网失败流程尚未接入，因此不能用固定演示验证这些能力。

## 检查命令

在 `my-app` 目录运行：

```powershell
node --test
npm run build
```

前一条运行现有规则测试；后一条检查能否构建页面，产物在被 Git 忽略的 `dist` 文件夹。两条命令均不能代替浏览器里的人工核对。

## Day 25｜可复用的发布前检查

在 Codex 中要求“使用 my-app/.agents/skills/verify-project 的 verify-project Skill 检查当前项目”，或在 my-app 目录手动运行：

```powershell
node .agents/skills/verify-project/scripts/verify.mjs --report day25/check-20261020-1
```

检查会逐项输出 PASS/FAIL、命令和实际证据，涵盖既有回归、构建配置、项目范围内的密钥规则、公网资源、线上版本、健康接口及跨域预检；不自动部署或操作真实业务记录。JSON、Markdown与HTML报告保存在本地 `_logs/day25/`，由 Git 忽略。每轮换一个新的 `--report` 名称；同名报告会被拒绝覆盖，以保留前一轮证据。

用错误发布地址验证它不会虚报通过（只改变本次检查输入，不改线上）：

```powershell
node .agents/skills/verify-project/scripts/verify.mjs --site http://localhost:5173 --report day25/fault
```

预期公网目标项明确 FAIL，总结果 FAIL。保存该轮证据后，去掉 `--site` 参数重跑默认地址，另存报告。退出0仅表示本轮自动项全过；退出1表示有失败/未验证项；退出2表示参数或执行过程不完整，均需查看证据。真实会话、云数据库权限与CRUD未执行时仍是“未验证”，不能用本地模拟测试替代。

本地开发服务器运行时，可打开 `http://localhost:5173/_logs/day25/fault.html` 查看故障报告并截图。报告应同时显示错误输入、对应FAIL和具体原因。详细检查标准与历史踩坑依据见 [verify-project Skill](.agents/skills/verify-project/SKILL.md)。
