## 4. PostgreSQL 导出数据：已核实的按钮路径

本项目不是文档型数据库；不使用“集合管理 → 导出JSON”流程。

本轮在侧边浏览器实际打开：
**SQL 型数据库 → 数据编辑器 → schema public → entries 左侧表名右侧的菜单 → 导出数据 → 导出为 CSV／导出为 SQL**。

注意：“entries表名右侧菜单”指左边表列表中的菜单。数据表上方、管理员角色旁的另一处更多菜单，本轮只有“调用方式”，不是导出入口。

### 你实际导出时这样做

1. 点左侧“SQL 型数据库”。
2. 点“数据编辑器”；核对schema为 public。
3. 在左边表列表找到 entries，点该表名右侧的菜单。
4. 点“导出数据”。
5. 日常查看副本点“导出为 CSV”；需要SQL形式的数据文件时点“导出为 SQL”。按你的用途选择，不必两份都导出。
6. 浏览器有保存提示时，保存到自己掌握的本机私有目录；建议用含日期的文件名。不要存入源码、Git提交目录或静态托管目录。
7. 看下载列表是否成功；记录文件名、大小、时间。只有菜单可见不算下载成功。
8. 打开本机文件核对列名、记录数和本次导出范围；如页面提供行数／筛选范围选项，逐字记录实际选项。CSV中原文可能有换行，不能用文件文本行数当记录数。
9. 用同一时点的只读表记录数核对；若同时有人写入或有筛选，说明差异，不强行记“完整”。
10. 在下表记录实际结果。若导出其他现有业务表，分别记录 favorites、reading_notes，不把只导出entries叫作整库备份。

本轮只展开菜单，实见“导出为 CSV”“导出为 SQL”，没有点击最终格式、没有下载，所以下载后是否另有范围弹框、导出能否成功、实际文件内容与行数均未验证。CSV仅是数据副本；SQL导出是否包含结构、索引、约束、权限等，须检查实际文件，不能预先宣称可完整恢复。

导出的业务数据本身可能含私人原文和身份字段。你只需回传导出状态、格式、行数等检查结论；不要把数据文件或其中原文放进交图或Git。
