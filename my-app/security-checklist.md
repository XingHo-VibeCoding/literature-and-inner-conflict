## 审计发现与修复

| 审计发现 | 修复 | 验证方法 |
| --- | --- | --- |
| 非法 UTF-16 记录 ID 会抛出 `URI malformed` | 在编码 ID 前校验，返回“记录 ID 无效，请重新读取记录。” | `publicApi.test.js` 的非法 ID 用例；断言 INVALID_INPUT 且请求计数 0 |
| 原文为 null、缺对象或非文字感悟会裸抛 `TypeError` | 共享校验先检查类型，返回原文/感悟的中文说明，不把数字或对象转成正文 | `shared/validation.test.js` 的缺对象、非字符串及原文保留用例 |
| 前端直接采用上游 message、fields 和任意错误码 | 请求层只使用固定中文、契约错误码及已登记字段；未知内容不透传 | `publicApi.test.js` 注入虚构英文错误、恶意字段及未知错误码，断言详情不出现 |
| 后端将已知 ApiError 的 5xx 消息与 fields 直接返回 | 所有 5xx 统一“服务暂时不可用，请稍后重试。”，隐藏 fields，保留状态、错误码、重试标记与关联 ID | `reads.test.js`、`writes.test.js` 的已知500/503和未知异常脱敏用例；`cors.test.cjs` 核对封套与CORS |
| `.env.example` 缺失且会被 `.env.*` 忽略 | 添加只含公开示例地址和空密钥的模板，只为该模板增加例外 | `git check-ignore -v -- .env .env.local .env.example`；模板应显示否定例外，真实配置仍被忽略 |

## 三类错误的统一提示

| 类型 | 示例触发 | 用户看到的中文 | 数据保护 |
| --- | --- | --- | --- |
| 输入错 | 日期/正文/类型/ID/版本无效 | 按字段说明，如“记录 ID 无效，请重新读取记录。”、“原文须为文字，请检查输入内容。” | 无效输入先停止，不改写原文，不发不必要请求 |
| 网络错 | 安全注入 fetch 拒绝；超时单独保留中文提示 | “网络请求失败，请核对网络连接与跨域配置后再手动重试。” | 草稿保留，不自动重试写入；结果不明先只读核对 |
| 服务端错 | 安全注入 JSON/HTML 500、502、503 | “服务暂时不可用，请稍后重试。” | 不展示 SQL、栈、上游 message/fields，不伪装为空列表 |

## 若日后发现真实密钥

1. 立即停止相关发布，在供应商的密钥管理页作废泄露密钥；只删源码或改Git历史不能让旧密钥失效。
2. 在云平台安全生成替代密钥，按原有最小权限和有效期配置；秘密只更新对应服务端环境/平台注入，不放入VITE_、仓库、日志或截图。遇到需要输入新认证凭证的界面，由用户在该页完成输入。
3. 重新部署受影响服务，验证新配置可用；从供应商控制台确认旧凭证已撤销，再检查异常使用记录及必要的其他凭证。
4. 清理当前代码中泄露值并复跑扫描，保留脱敏位置/处置回执。需要重写已公开Git历史时另行协调，不能用强制推送代替作废。
